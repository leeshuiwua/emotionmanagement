# 观心镜：生活账本与个人心情记录
更新时间：2026-09-13。状态：本地实现；真实微信/模型联调与部署另行验收。

## 产品边界
每个接入渠道与微信消息发送者的组合拥有独立生活账本及心情档案，不推测接入号主人或聊天对方的人格。管理员可查看全部已接入用户的记录；并非普通用户自助后台。跨渠道同一人不自动合并。

## 消息处理
| 输入 | 动作 | 微信反馈 |
| --- | --- | --- |
| 明确真实收支 | 自动入账，最多10笔，金额使用整数分 | 日期、方向、金额、分类、账户 |
| 本人的心情或感受 | 保存心情原文和消息类型 | 已记录，可在后台回顾 |
| 明确收支和本人心情同时存在 | 一个事务中分别保存 | 入账结果＋心情已记录 |
| 含糊不清 | 不写业务数据，请用户重新完整说明 | 补充金额、用途或本人感受 |
| 超出范围 | 不写账本/心情档案 | 仅支持生活记账与心情记录 |
| 模型失败 | 不冒充识别结果，不新增业务数据 | 暂时不可用，请重新发送 |

显式“查账”读本人本月收支。旧“确认记账/取消记账”仅用于兼容已有草稿，新消息不再创建草稿。语音依赖 iLink 已返回的转写文本，未配置原始语音 ASR。明显危机表达优先现有本地安全支持，不执行自动财务写入；关键词安全分流不是完备的危机识别系统。

## 后台心境回顾
按北京时间筛选记录人和日期。自动分析所选人的最近50条记录（XML可调），每条最多2000字符；显示本次样本量、总量、截短标记、模型名、生成时间和原文证据。
分别给出最近心境、变化线索、表达/性格倾向、具体调节建议及样本局限。移除关键词MBTI和心理数值评分。模型不得做疾病诊断或稳定人格定论；输出的证据ID必须属于本次样本。
记录快照、模型版本或提示词改变后重新分析；相同快照缓存，同一进程内并发合并。分析失败保留原记录并允许重试，不回退到伪造画像。

## 实现与数据
TypeScript、Express、React、SQLite，单机部署。沿用 inbound_messages/conversations 保存心情；ledger_entries 保存收入支出，mood_analyses 新增缓存。
分类、入账、心情记录有独立测试；混合写入与幂等在同步事务中完成，网络请求在事务外。配置保持 XML 管理，校验失败启动报错，不静默忽略。
模型配置复用后台激活的日常模型，支持 deepseek-v4-flash / pro 的非思考 JSON 输出，不硬改用户已激活配置。

## 验收与已知边界
- 自动收支、混合记录、不支持内容、含糊输入与接口故障分流。
- 并发/重复消息不重复入账；混合写入失败整体回滚；账号、渠道隔离。
- 月度收支、软删除、旧草稿不阻塞新账目。
- 个人最新样本、证据ID校验、缓存失效、认证/CSRF、北京时间边界。
- 当前测试中的模型回复是受控模拟，不代表真实模型分类准确率。
- 旧历史聊天没有重新分类，可能含此前收集的闲聊；保留原数据，不能把历史样本视为已按新规则筛选。
- 澄清后需发送完整内容，暂不支持跨消息补全字段。超出10笔请分批。
- 微信发送失败后的可靠重发队列、历史清洗、用户自助访问授权、原始语音识别属于后续工作。

## 发布与回滚
发布前停止服务并备份 SQLite（含未checkpoint的WAL）与配置；建议使用 SQLite 在线备份工具得到一致性备份，不能只复制活跃db文件。
执行 npm ci、npm run build，再重启。前后端与 XML 必须同版本发布；新的 profiles API 不再返回旧MBTI等字段。
启动仅新增缓存表，不清空历史、不自动确认旧草稿。回滚代码与XML成套恢复；回滚前备份升级期间的新记录，不直接用旧备份覆盖新账目。
不得将数据库、微信凭据、模型密钥或真实心理记录上传 Git。
