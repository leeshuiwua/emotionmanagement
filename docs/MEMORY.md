# 微信长短期记忆（第一期）

## 使用方式

后台「洞察心境」选择记录人，查看「长期画像」「当天上下文」「记忆条目」。记录人是发送消息的微信用户，不是接收消息的机器人账号。身份以渠道 ID + 发送者 ID 隔离；不自动合并不同渠道或重新创建的渠道。

- 日期筛选仅影响下方心情记录和近期分析，不影响长期画像和记录人目录。
- 当天上下文按北京时间零点切换；意图识别读取当天最近 16 条消息和当日摘要。已完成的记账不应再被提取，只补全最近尚未解决的澄清。
- 长期记忆无自动过期，保留原始证据、发生时间和更正说明。短期指上下文窗口，不代表原始记录一天后删除。
- 长期画像展示观察、反向证据、变化和局限，可展开原文；不提供确定 MBTI、疾病诊断或精神健康评分。
- 纯记账内容只参与当天上下文，不作为性格证据。历史心情记录导入时由模型再次筛除测试消息和无效内容。
- 更正记忆会使该条退出后续画像，并重建画像。更正说明是管理员批注，不作为用户自述证据。
- 清除单个记录人会清除该人的心情、原文、摘要、记忆、画像和任务；账本和微信绑定保留。全局清除心情记录同时清理全部记忆。页面操作不能恢复，操作前自行备份。

## 数据流与部署

消息 → 意图识别（当天上下文）→ 原子保存业务记录与记忆事件 → 微信简短确认。

后台定时任务 → 按日、每批最多 20 条归纳 → 存储摘要和带证据的记忆。查询后台时发现画像过期，会排队更新；已有画像仍可先看。点击更新可重试失败任务。任务每 2 秒调度，失败退避重试，连续 5 次失败后暂停；新消息或手动更新重新排队。

画像每次从全部未失效记忆开始分批归纳，不限最近多少天；每批携带上一批总结，模型可能损失细节，因此不是无损检索或心理测评。不会把所有历史原文一次塞入模型。记忆条目页当前展示最近 100 条，画像仍使用全部有效条目。

SQLite 启动时增量建表并幂等导入已有心情记录，无需手工执行 SQL。部署前备份数据库，执行 `npm run build`，重启服务。后台复用已激活的常规模型配置，支持当前 Flash 配置，提示词及批次、超时、输出限制位于 `src/server/config/prompts.xml` 的 `memory` 节点；修改后重新构建并重启。

当前实现是单进程持久化任务队列，与现有 SQLite/微信轮询架构一致。不要让多个服务实例同时处理同一数据库。进程重启恢复未完成任务；消息去重、事务、账号隔离和清理代际检查防止重复或已删除内容回写。

## 成本、隐私和限制

每个归纳批次调用一次模型；长期画像每 20 条记忆追加一次归纳调用。首次导入较多历史时会增加耗时和 token 消耗，不阻塞微信记账确认。模型失败不影响已保存的业务记录。尚无每日硬性费用上限。

归纳和画像请求含用户原文，将发给后台所配置的模型服务；部署者应确保用户知情和授权。Flash 日志开关同样覆盖 `memory`、`profile` 工作负载，生产建议 `FLASH_LOG_LEVEL=summary` 或 `off`，避免完整原文出现在日志。删除数据库记录不会清除已有外部模型日志或运维备份。

权限沿用管理员登录，修改接口要求 CSRF。测试使用模拟模型和独立数据库；真实 Flash 对长历史总结和省略表达的质量仍需用已获授权的样本验收。未来多实例、向量检索、跨渠道身份合并均不在本期范围内。
